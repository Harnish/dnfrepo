# dnfrepo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go web service that manages many signed dnf/yum repos with pipelines (dev, test, prod), per-repo access modes, sources, uploads, promotion, browse pages, `.repo` files and RSS feeds, plus a React admin UI.

**Architecture:** One Go binary serves three things: the repo file tree under `/r/<slug>/` (guarded by per-repo access middleware), a JSON admin API under `/api/`, and the built React app. PostgreSQL holds state; rpm files and `createrepo_c` output live on disk under the data dir. Every repo mutation (upload, source fetch, promote, delete) funnels through one `publish.Rebuild`, which runs `createrepo_c`, signs `repomd.xml`, and swaps the result in atomically.

**Tech Stack:** Go 1.26, `net/http` (Go 1.22+ pattern mux), `pgx/v5`, `github.com/go-mail/mail` (verification email), `github.com/sassoftware/go-rpmutils` (rpm header), `github.com/ProtonMail/go-crypto/openpgp` (signing), `createrepo_c` binary, React + Vite + TypeScript.

**Spec:** `docs/superpowers/specs/2026-10-30-dnfrepo-design.md`

## Global Constraints

- Backend Go; state in PostgreSQL; frontend React talking to the Go JSON API.
- Admin sign-in: email is the user id, verified by a verification email sent with `go-mail/mail` (never `net/smtp`).
- Repo metadata built by `createrepo_c` and GPG signed (`repomd.xml.asc`); generated `.repo` files set `repo_gpgcheck=1`, `gpgcheck=0`, and `gpgkey=<BASE_URL>/gpg.key`.
- Exactly one access mode per repo: `public`, `ips`, or `users` (Basic auth, username + token). Modes never mix.
- Access mode covers everything under `/r/<slug>/`: rpms, `repodata/`, browse page, `feed.xml`, `<slug>.repo`.
- Only a first-stage repo (no `previous`) accepts uploads and sources. Later stages get packages only by promotion from their direct previous repo. Server-enforced.
- Promotion is all-or-nothing, copies (hardlink on same filesystem), originals stay.
- GitHub source rule from `rpmdl`: latest release, `.rpm` asset whose lowercase name contains `x86_64` or `amd64`; if the filename has no `\d+\.\d+`, append `-<tag without leading v/V>` before `.rpm`. Plex: `https://plex.tv/api/downloads/1.json`, distro `redhat`, build `linux-x86_64`.
- `X-Forwarded-For` honored only from peers in `TRUSTED_PROXIES` (empty by default).
- Tokens stored hashed; shown once; never logged. GPG private key never logged or returned by the API.
- Repo-user usernames must not contain `:`.
- Dockerfile: multi-stage, pinned base images, non-root, HEALTHCHECK; `.dockerignore`; `.github/workflows/docker-build.yml` (push to main, tags: commit SHA and `latest`, ghcr.io); `.gitlab-ci.yml` with dind.
- Conventional commits. **Never commit without asking the user first**; commit steps below mean "ask, then commit".

## Review Focus

1. Path traversal: `../` or absolute paths in uploaded filenames and in `/r/<slug>/<path>` requests must never read or write outside the repo dir. Expect 400/404.
2. IP spoofing and formats: `X-Forwarded-For` from an untrusted peer is ignored; IPv4-mapped IPv6 (`::ffff:10.0.0.5`) matches an IPv4 CIDR.
3. Promotion conflict: promoting a file that exists in the target with a different checksum fails the whole promotion and leaves the target unchanged.
4. Deleting a repo in the middle of a chain: rejected while it has a next or previous repo (admin must unlink first).
5. Leaks through side doors: a `users`/`ips` repo's browse page, `feed.xml`, and `.repo` file return 401/403 the same as its rpms; a non-rpm file uploaded as `.rpm` is rejected and leaves no file on disk.

## File Structure

```
cmd/dnfrepo/main.go          wiring, graceful shutdown
internal/config/             env config
internal/store/              pgx queries + embedded SQL migrations
internal/adminauth/          admin accounts, email verification, sessions, bootstrap/invite
internal/rpmmeta/            rpm header parsing

internal/publish/            per-repo lock, createrepo_c, sign, atomic swap
internal/access/             client IP, per-mode middleware, throttle
internal/pipeline/           upload, delete, promote (the only writers of package files)

internal/api/                admin JSON API handlers
web/                         React admin UI (Vite)
Dockerfile .dockerignore .github/ .gitlab-ci.yml README.md
```
